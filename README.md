# Architecture Diagrams

An interactive multi-lens diagram tool: one graph, viewed through several togglable perspectives instead of several separate static diagrams.

- **Nodes are stable** — the same components exist across every lens, preserving spatial memory.
- **Edges are lens-scoped** — each edge belongs to one or more named "edge sets" (e.g. Control Flow / Data Flow) that can be toggled on or off independently, alone or combined.
- **Hierarchy is orthogonal to lens** — nodes can be grouped into collapsible subsystems, nested arbitrarily deep (a Step Function inside an AWS account, an AV Lambda inside the same account, and so on). Collapsing a group merges its children's edges into the external world into single deduplicated lines (no redundant parallel edges), and correctly resolves an edge drawn directly against a container itself (not one of its children) at any collapse depth.
- **Node-lens grouping is a third, independent axis** — spatially regroups the *nodes themselves* into on-screen regions by any metadata key currently in use (e.g. `permissionScope`), for questions the structural tree can't answer on its own. A node with no value for the active key rides along with its nearest tagged ancestor; a node with its own explicit tag breaks free into its own region regardless of nesting depth, so e.g. four IAM roles spread across two unrelated AWS-account containers can converge into one shared "security" region. An incomplete bundle (something inside it broke away) gets a dashed border and a `visible/total` fraction badge instead of a plain count. See `src/engine/nodeLens.ts`.
- **Actors, actions, and triggers** — a node can be flagged as an actor (an IAM role, a person, anything that *does* things); an edge can be attributed to one via `actorId`, independent of its own source/target, since the actor performing an action isn't necessarily either endpoint (an IAM role copying between two S3 buckets it isn't itself drawn connected to). Every such action renders a small anchor at its own midpoint carrying the actor's icon. A **trigger** is just a plain edge whose target is that anchor instead of a real node — a process step pointing at the *specific* action it causes, not just the actor in general. See `src/engine/actorAnchor.ts`.
- **Edges can be reassigned by dragging** — select a single (unmerged) edge and drag either endpoint onto a different node or actor-anchor to reattach it in place, instead of deleting and recreating it.
- **Auto layout, two ways** — a container can be set to Figma-style auto layout (`vertical`/`horizontal`, a configurable gap), stacking its own children by sort order instead of literal stored positions; separately, "Run graph layout" is a one-shot, crossing-minimizing (elkjs) layout over a container's children (or every top-level node), for tidying up a manually-placed diagram without adopting auto layout permanently.
- **Bulk actions** — marquee-select (shift-drag) multiple nodes or edges at once to wrap a node selection in a new container (Figma's "wrap in frame"), bulk-delete, or bulk-toggle an edge selection's anchor between fixed and floating geometry.
- **Hierarchy panel** — a tree view of the same nodes, supporting drag-to-reorder/reparent, and a context menu for duplicating a subtree or expanding/collapsing it all at once.
- **Frames capture narrated walkthroughs** — a frame is a saved snapshot of which lenses are active, which nodes are expanded, what's highlighted, and (optionally) which node-lens grouping is showing, so an author can build a guided sequence a viewer can step through. "Edit highlights" puts the canvas into a click-to-toggle mode for building that highlighted set node/edge by node/edge, live. A frame can also carry several draggable **sticky notes** — small annotation cards positioned directly on the canvas, visible only while their owning frame is active — distinct from a frame's single `notes` caption. The current frame is mirrored into the URL as `?frame=<id>`, so a link resumes at that exact frame; an "✕ Exit frame view" control returns to "Not viewing a frame" without disturbing whatever lens/expand/grouping state that frame left you in.
- **Hovering** a node or edge highlights everything connected to it and dims the rest — including an actor's own actions when you hover the actor itself, even though it's neither endpoint of any of them.
- **Metadata autocomplete** — every key/value already used anywhere in the diagram is offered back via native `<datalist>`s when adding new metadata, so a category like `type` doesn't silently fork into `type`/`types` across nodes.
- **Share a diagram via URL, read-only by default** — "Copy share link" packs the whole diagram (gzip'd, base64url-encoded, no backend involved) into a `?d=` query param and copies it to the clipboard, carrying the current frame along if you're viewing one. Opening that link loads the diagram the same way "Import JSON" would, but flips on a read-only **view mode** first: dragging, right-click menus, property panels, and every authoring control disable themselves (down to the same central guard every diagram-mutating store action already shares, not just hidden buttons — see `persistAndSet` in `src/store/diagramStore.ts`), so opening someone else's link can never be mistaken for editing your own working diagram. A prominent "Edit" button restores full editing at any time.

## Running it

```bash
npm install
npm run dev
```

Opens with a small seeded demo diagram — a real-world AWS ingest pipeline (Step Function → S3 buckets → AV-scanning Lambda → cross-account copy, two AWS account boundaries, four IAM roles attributed to the actions they perform) that exercises collapse-merge at multiple nesting depths, the actor/action/trigger model, and a 4-frame walkthrough. Its nodes also carry a `permissionScope` metadata tag demonstrating node-lens grouping: group by that key and all four IAM roles — three structurally nested in one AWS account, one in the entirely separate other account — converge into a single shared region, distinct from either account's own. The toolbar's "Load example…" dropdown also has two smaller, more focused examples: a three-tier web app (built to show merge-on-collapse as simply as possible) and an order-processing flow (the actor model in a non-AWS domain) — see `src/data/examples/`.

### Authoring a diagram with an AI

[`docs/ai-authoring-guide.md`](docs/ai-authoring-guide.md) is written to be handed directly to an AI (in a prompt or as a reference file) that needs to generate a `Diagram` JSON document from scratch — the full schema, positioning/spacing conventions, the actor/action/trigger and node-lens patterns worked through with real examples, and a referential-integrity checklist for everything import validation doesn't check for you.

```bash
npm run build   # type-check + production build
```

## Testing

```bash
npm run test       # Vitest + React Testing Library (engine + component tests)
npm run test:watch # same, in watch mode
npm run test:e2e   # Playwright, driving a real browser against the dev server
```

Unit/component tests live next to the code they cover (`*.test.ts(x)`); end-to-end tests live in `e2e/` (`diagram.spec.ts` for the core interaction model, `nodeLens.spec.ts` for grouping, `frameAnnotations.spec.ts` for frame exit/sticky notes, `shareView.spec.ts` for share links and view mode). The Playwright suite exercises the full interaction model against a real browser — lens toggling, collapse/expand with edge merging, hover highlighting, frame playback, drag-to-connect edge creation, node-lens grouping, sticky-note dragging, and the whole share-link round trip — and is what actually caught several real bugs, not just regressions: hovering a node mid-drag was corrupting React Flow's hit-testing for the handle under the cursor (fixed in `GraphNode.tsx`/`GraphEdge.tsx` by freezing hover while a connection is in progress), dragging a node-lens-detached node — or bulk-wrapping a lens-detached selection into a new container — was silently writing the lens's temporary region-slot position into the diagram's real, persisted position (fixed by disabling both while a lens is active; see `EffectiveNode.lensDetached` in `src/types/effectiveGraph.ts`), and an unhandled promise rejection surfaced from feeding malformed data into `DecompressionStream` while testing the share-link codec's own error path (fixed by properly chaining/catching the writer-side promise instead of firing it and forgetting it).

`src/data/examples/index.test.ts` validates every shipped example diagram's structural integrity (every id reference resolves to something real, every trigger's anchor points at an action edge that actually has an actor, `computeEffectiveGraph` doesn't throw for any frame) — a safety net for editing the demo data itself, not just the engine.

Note: Node 22+ defines its own experimental global `localStorage`, which otherwise wins over jsdom's actually-functional one at the same bare-global slot in every test that touches persistence. `vitest.config.ts` disables it (`--no-experimental-webstorage`) and `persistence.ts` uses `window.localStorage` explicitly rather than the bare identifier, so this is unambiguous in both a real browser and the test runner.

## Deploying to GitHub Pages

```bash
npm run deploy:pages
```

Builds the app and pushes `dist/` to the `gh-pages` branch (via a throwaway git worktree, so it never touches your working tree on `main`). One-time setup in the repo: **Settings → Pages → Source: Deploy from a branch → `gh-pages` / `(root)`**. Vite's `base` is set to `./` (relative) so the build works from any subpath without hardcoding the repo name.

## How it works

- **`src/types/diagram.ts`** — the persisted schema: `DiagramNode`, `DiagramEdge`, `EdgeSet`, `Frame`, `StickyNote`, `Diagram`. A diagram is a single JSON-serializable document. Everything added since the original model (`isActor`, `actorId`/`sourceHandle`/`targetHandle`, `autoLayout`, `nodeLensKey`, `stickyNotes`) is optional, so older exported JSON still imports fine. See `docs/ai-authoring-guide.md` for the full schema plus authoring conventions.
- **`src/engine/`** — the core derivation logic. `computeEffectiveGraph` takes the raw `Diagram` plus the current view state (active edge sets, expanded nodes, hover/frame highlights) and produces the graph that actually gets rendered: it resolves each node/edge endpoint to its nearest visible (collapsed) ancestor, then dedupes and merges edges that resolve to the same pair, unioning their sets and combined metadata. A remembered edge anchor and an action's `actorId` both carry through as long as the merge resolves to exactly one raw edge — a collapsed ancestor standing in for the real endpoint is still a real node with its own border and handles, not a reason to fall back to floating geometry. `ancestry.ts` holds the ancestor-resolution walk that ordinary collapse and an edge drawn directly against a container share with no special-casing, at any nesting depth (it's also where a node's inherited color resolves, CSS-style, up its `parentId` chain). `actorAnchor.ts` defines the `anchor:<edgeId>` id scheme a trigger edge's `targetId` uses to point at a specific action instead of a real node. `nodeLens.ts` computes node-lens grouping — which nodes become independent "bundle roots," which ride along with an ancestor, and each region's crossing-reduced stacking order (one left-to-right barycenter sweep). `containerLayout.ts` sizes containers and computes Figma-style auto-layout child positions; `graphLayout.ts` wraps elkjs for the one-shot "Run graph layout" action.
- **`src/store/diagramStore.ts`** — a Zustand store holding the diagram document plus the view axes (active edge sets, expanded nodes, node-lens key, current frame, read-only `viewMode`, and the frame-highlight-editing mode) and all CRUD/authoring actions, including the cascade rules for actors/actions/triggers (deleting an action edge or its actor cleans up any trigger left pointing at nothing) and per-frame sticky-note CRUD. Every diagram-mutating action funnels through one `persistAndSet` helper, which is also the single point `viewMode` gates — a shared/viewed diagram can't be edited by any path, not just whichever buttons happen to be hidden. The diagram auto-saves to `localStorage` (debounced); a successful JSON import (including one loaded from a `?d=` share link — see below) is separately snapshotted so "Reset to imported" can return to it even after further edits; view state resets on reload, and always resumes in full edit mode however the diagram was loaded.
- **`src/utils/urlDiagramCodec.ts`** — packs a `Diagram` into a URL-safe string for the `?d=` share-link param: JSON → gzip (native `CompressionStream`, no dependency) → base64url, with a plain-base64 fallback for browsers without `CompressionStream`. `App.tsx`'s init effect decodes it (alongside the existing `?frame=` deep link) on first mount, imports it, and flips on `viewMode`.
- **`src/components/Canvas/`** — the React Flow canvas: custom node rendering for leaf/collapsed-group/expanded-container/actor-anchor states, custom floating edges (so edges reattach correctly as nodes toggle collapse state), drag-to-reassign edge endpoints, the inline popover for tagging a newly-dragged edge's sets (and, for a real node-to-node connection, its actor), node-lens region labels/dividers, and `StickyNotes.tsx` (draggable per-frame annotation cards, positioned in the same canvas coordinate space as a node via `screenToFlowPosition`-diffed dragging).
- **`src/components/Panels/`** — lens toggles, the node-lens grouping picker, hierarchy tree (drag-to-reorder/reparent, duplicate, expand/collapse-all), node/edge property editors (including the Actor toggle and the actor-attribution dropdown), and the frame sequencer (author, highlight-edit, and playback).
- **`src/data/seedDiagram.ts`** — the demo diagram shipped with the app; **`src/data/examples/`** — the full gallery, including the seed.

## Non-goals (for now)

No backend, no in-app natural-language authoring assist (see `docs/ai-authoring-guide.md` if you want an *external* AI to generate the JSON directly), no schema-level validation rules beyond the shape check on import. Node position is still a deliberate authoring choice by default — nothing runs automatically on load — but both auto-layout mechanisms above exist for whenever you'd rather not hand-place things. Diagrams are shared as JSON files via the Export/Import buttons in the toolbar, or as a link to a specific frame via the `?frame=` URL param.
